# Bookmarks API

![Go Version](https://img.shields.io/badge/Go-1.27-00ADD8?logo=go)
![License](https://img.shields.io/badge/license-MIT-green)
![Status](https://img.shields.io/badge/status-live-brightgreen)

**A secure, production-ready REST API for managing private bookmarks and API keys.** Built with Go, Postgres, JWT, and strict per-user ownership — no HTTP framework, just the standard library.

## The Problem

Most bookmarking tools are either public, lack proper data isolation, or rely on heavy third-party SaaS platforms. If you are building a product that needs to store users' private bookmarks with tags, or if you need to issue secure API keys for machine-to-machine integrations, you need a backend that guarantees **absolute data isolation** and doesn't leak information through side channels.

This API solves that. It provides a hardened backend designed to handle authentication, authorization, and data storage with production-grade security practices out of the box.

## Features

- **JWT Authentication:** Short-lived access tokens (15 min) and opaque refresh tokens (7 days) with rotation.
- **API Keys (Machine-to-Machine):** Generate, list, and revoke API keys for external integrations. Keys are hashed with SHA-256 before storage and shown only once during creation.
- **Refresh Token Reuse Detection:** Presenting a revoked token immediately revokes every session for that user (mitigating token theft, following RFC 9700).
- **Strict Ownership:** Every SQL query is scoped by user ID. Cross-user access returns `404` (hiding existence) instead of `403`.
- **Timing Attack Mitigation:** Dummy bcrypt verification on unknown emails ensures the login takes the same time whether the account exists or not.
- **Multi-Layer Rate Limiting:** Token bucket per IP (normalized to /64 for IPv6) **and** per email on authentication endpoints.
- **CORS Ready:** Built-in middleware to allow requests from the Nuntix Frontend (localhost and production domains).
- **SSRF Protection:** When fetching page titles for bookmarks, private, loopback, CGNAT, and link-local IPs are blocked at the TCP dial level.
- **Event-Driven:** Publishes `bookmark.created` events asynchronously (Fire-and-Forget) to a separate Webhook Dispatcher service.
- **Zero Framework:** `net/http` with Go 1.22+ `ServeMux` patterns; `database/sql` with `pgx` driver.

## Tech Stack

| Layer | Choice |
|---|---|
| Language | Go 1.27 |
| HTTP | `net/http` (stdlib) |
| Database | Postgres 17 |
| DB driver | `github.com/jackc/pgx/v5/stdlib` |
| Auth | JWT HS256 + opaque refresh tokens |
| Password hashing | `golang.org/x/crypto/bcrypt` (cost 12) |
| Migrations | Versioned `.sql` files, embedded via `//go:embed` |
| Container | Docker (multi-stage, `alpine` runtime) |

## Quick Start

### Prerequisites
- Go 1.27+
- Docker and Docker Compose

### 1. Clone and Configure
```bash
git clone https://github.com/Carlos20052030/bookmarks-api.git
cd bookmarks-api
cp .env.example .env
```
Generate secrets and paste them into `.env`:
```bash
openssl rand -base64 32   # POSTGRES_PASSWORD
openssl rand -base64 48   # JWT_SECRET
```

### 2. Start Postgres and Run
```bash
docker compose up -d db
make run
```
The server listens on `:8080`. Migrations run automatically on boot.

### 3. Verify
```bash
curl http://localhost:8080/health
# {"status":"ok"}
```

## API Endpoints

### Public
| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Liveness probe |
| `POST` | `/auth/register` | Create account, returns tokens |
| `POST` | `/auth/login` | Exchange credentials for tokens |
| `POST` | `/auth/refresh` | Rotate refresh token, get a new pair |
| `POST` | `/auth/logout` | Revoke refresh token |

### Protected
Require `Authorization: Bearer <access_token>`.
| Method | Path | Description |
|---|---|---|
| `POST` | `/bookmarks` | Create bookmark |
| `GET` | `/bookmarks` | List with pagination and `?tag=<uuid>` filter |
| `GET` | `/bookmarks/{id}` | Get one with tags |
| `PUT` | `/bookmarks/{id}` | Update |
| `DELETE` | `/bookmarks/{id}` | Delete |
| `POST` | `/bookmarks/{id}/tags/{tagID}` | Attach tag |
| `DELETE` | `/bookmarks/{id}/tags/{tagID}` | Detach tag |
| `POST` | `/tags` | Create tag |
| `GET` | `/tags` | List tags |
| `DELETE` | `/tags/{id}` | Delete tag |
| `POST` | `/api-keys` | Generate a new API Key (returns raw key once) |
| `GET` | `/api-keys` | List active and revoked API keys |
| `DELETE` | `/api-keys/{id}` | Revoke an API key |

## Design Notes

- **UUIDs everywhere.** Sequential IDs leak information. UUIDv4 makes enumeration infeasible.
- **`404`, not `403`, for another user's resource.** `403` confirms the resource exists; `404` is indistinguishable from "not found".
- **SHA-256 for tokens and API Keys, bcrypt for passwords.** Tokens and API Keys generated by `crypto/rand` carry 256 bits of entropy. Passwords are low-entropy and need the bcrypt work factor.
- **API Key Prefix.** Keys are prefixed with `nuntix_live_` to help secret scanners (like GitHub's) identify leaked credentials.
- **Refresh token rotation.** Every refresh revokes the old token and issues a new one. A reused token signals theft and revokes every session for that user.
- **Migrations in transactions.** Each migration runs in its own transaction and is recorded in `schema_migrations`.
